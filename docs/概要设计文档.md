# 概要设计文档

## 1. 基线与参与者

本文承接[架构设计](架构设计文档.md)，给出后续编码的业务与接口基线。当前内容为设计，仓库尚无对应实现。

接警员负责核实和受理；指挥员负责派遣、增援和预案审批；出警人员负责接收、到场与反馈；运维人员负责基础设施维护，默认无权查看警情正文；审计人员按授权查询审计记录。

## 2. 核心业务流程

1. 接入适配器登记 channel、sourceId 和 callId，以渠道与来源标识防止同一次请求重复建单。电话重拨是否属于同一警情，由关联规则和人工核实决定，不能只凭手机号合并。
2. 事务内创建待核实警单及 IncidentCreated 事件。呼叫建立继续通过 CTI 处理，定位、地图、视频和转写异步启动。
3. 接警员核实地址、类型和紧急程度。定位结果必须展示来源、采集时间与精度；迟到结果不覆盖人工锁定地址。
4. 推荐引擎根据辖区、能力、在线状态、位置新鲜度和负载给出候选；500 米仅作可配置初始范围，无合适警力则扩大范围或转人工。
5. 经权限策略确认派遣，事务内写入派遣任务及通知事件。自动派警仅在明确授权条件下开放，默认保留人工确认。
6. 终端回执驱动任务状态更新；未确认或离线进入超时处置，提醒调度员并通过授权渠道补充联络，不能把通知送达当成已经出警。
7. 出警人员上报出发、到场和处置结果，接警员或指挥员复核结案。更正、撤销和重新打开均保留原因与历史。

三方通话建立失败时保持已有通话，展示失败状态并提供人工转接。辅助系统失败不撤销已经受理的警单。

## 3. 状态与并发控制

| 对象 | 主要迁移 | 约束 |
| --- | --- | --- |
| 警单 | 待核实 → 已受理 → 处置中 → 待复核 → 已结案 | 已受理后才可正式派遣；首个有效派遣进入处置中 |
| 警单例外 | 待核实 → 已撤销；已结案 → 待复核 | 撤销或重开需相应权限、原因与审计；活动任务须先协调终止 |
| 派遣任务 | 待确认 → 已接单 → 已出发 → 已到场 → 已反馈 | 警单可对应多条派遣任务，结案前检查活动任务 |
| 派遣例外 | 待确认 → 已拒绝 / 已超时 / 已取消 | 超时后迟到接单需重新校验，不能直接激活过期任务 |
| 通知 | 待发送 → 已发送 → 已送达；失败 → 待重试 / 已隔离 | 与派遣状态独立，不用消息 ACK 替代业务回执 |

警单及派遣任务都带 version，更新使用条件写入；冲突返回当前版本，由操作员刷新后重试。警力占用通过事务内唯一约束或原子预约控制；增援等允许多人任务的情形另设规则，不以单一“忙碌”标记替代业务约束。

## 4. 逻辑数据模型

| 实体 | 关键字段 | 约束与用途 |
| --- | --- | --- |
| incident | id、sourceChannel、sourceId、status、priority、locationRef、version、createdAt | 渠道来源组合唯一；人工核实与原始定位分开保存 |
| call_session | id、providerCallId、incidentId、status、recordingRef | 厂商呼叫标识按接入方作用域唯一；一警单可关联多次通话 |
| dispatch_task | id、incidentId、unitId、status、commandId、deadline、version | commandId 唯一；任务超时按服务端时间计算 |
| unit_status | unitId、capabilities、availability、location、observedAt、version | 过期位置不得作为高置信推荐依据 |
| outbox_event | eventId、aggregateId、aggregateVersion、type、payload、publishState | 业务事务同时插入；按状态和创建时间扫描 |
| consumed_event | consumerName、eventId、processedAt | 组合唯一；与本地业务变更同事务 |
| retry_task | id、commandId、attempt、nextAttemptAt、state、lastErrorCode | 有限重试、租约领取、人工重放审计 |
| audit_record | id、actorId、action、targetId、result、reason、occurredAt | 禁止记录明文口令、完整敏感正文 |

录音与视频保存在独立存储，数据库保存引用、摘要、起止时间、访问权限和归档状态。业务数据删除、事件保留、去重记录清理与审计留存分别制定策略；去重窗口不能短于允许重放窗口。

## 5. 拟定业务 API

接口路径为设计草案，正式实现时提供 OpenAPI。统一 UTC 时间、请求追踪标识和结构化错误码；所有写接口进行身份、辖区和对象级权限检查。

| 方法与路径 | 输入要点 | 行为 |
| --- | --- | --- |
| POST /api/v1/incidents | channel、sourceId、核实信息 | 创建警单，返回 201 与 incidentId |
| GET /api/v1/incidents/{id} | 警单标识 | 返回授权字段及 version |
| PATCH /api/v1/incidents/{id} | expectedVersion、修改字段、原因 | 条件更新；版本冲突返回 409 |
| POST /api/v1/incidents/{id}/dispatches | unitIds、expectedVersion、确认依据 | 创建派遣任务，不承诺终端已接单 |
| POST /api/v1/dispatches/{id}/receipts | commandId、回执状态、expectedVersion | 幂等登记终端回执并校验合法迁移 |
| POST /api/v1/incidents/{id}/close | expectedVersion、复核结论 | 校验活动任务和必填项后结案 |

创建与派遣接口使用 Idempotency-Key，并将调用方、操作类型和键作为作用域。相同键和相同请求返回原结果；相同键但不同内容返回冲突。持久化请求摘要与结果，避免进程重启后失去去重能力。参数错误返回 400、未认证 401、无权限 403、依赖不可用且无法受理时返回 503；错误正文仅包含安全可公开的信息。

## 6. 事件与异步编排

统一事件信封包括 eventId、eventType、schemaVersion、incidentId、aggregateId、aggregateVersion、occurredAt、traceId、payload。事件不携带未经必要性评估的手机号、录音内容或精确住址，下游按权限查询详情。

| 事件 | 主要消费者 | 结果 |
| --- | --- | --- |
| IncidentCreated | 定位、地图、转写适配器 | 生成关联请求与辅助结果 |
| IncidentVerified | 推荐引擎 | 产生带版本和有效期的候选方案 |
| DispatchCreated | 通知适配器、协同服务 | 发送带 commandId 的终端命令 |
| DispatchStatusChanged | 接警台、指挥台、数据汇聚 | 展示当前任务及同步进度 |
| IncidentClosed | 归档、统计、数据汇聚 | 进入归档流程 |

按 incidentId 分区；同一警单事件的版本由事务内分配。消费者发现版本缺口时暂停该警单的有序副作用，查询事实或进入补偿流程，不阻塞所有警单。Schema 优先增加可选字段，破坏性变更使用新版本并安排兼容窗口。

## 7. 超时、补偿与降级

外部调用分别配置连接超时、总超时、重试上限和熔断策略。定位和视频失败返回明确的“不可用/过期”标记；语音转写故障转人工录入；推送失败保留任务并通知调度员；MQ 不可用保留 Outbox，恢复后限速补发。

重试仅针对可重试错误，使用退避和抖动；无幂等能力的通信命令先查询执行状态再决定重发。任务取消与迟到回执竞争通过版本和状态机裁决，必要时产生补偿命令和人工告警。重放工具必须展示影响范围并记录操作者与原因。

## 8. 验收场景

后续实现需验证重复呼入事件不会重复建单；同一派遣请求重试不会新增任务；并发派遣遵守警力预约规则；数据库提交后进程崩溃仍可补发事件；重复和乱序消费不会回退状态；离线终端及迟到回执可追踪；权限越界被拒绝并留痕；人工锁定地址不被异步定位覆盖。

性能验收把接通、建单、推荐、派遣提交、终端接单分别计时。录音证据完整性、应急人工流程及中心恢复按[部署文档](部署文档.md)组织演练。当前仓库没有执行上述测试，不能据此宣称验收通过。
