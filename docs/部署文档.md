# 部署文档

## 1. 适用范围与现状

当前仓库仅包含需求与设计 Markdown，没有 pom.xml、Gradle 工程、镜像、数据库迁移、Kubernetes 清单或 CI 工作流。因此本文是部署准备与上线验收方案，不能作为可直接执行的一键部署脚本。真实服务名称、端口、版本、容量与命令须在实现后补齐并验证。

关联文档：[架构设计](架构设计文档.md)、[概要设计](概要设计文档.md)。文中的部署拓扑是建议基线，生产上线前须通过业务、通信、网络、安全与运维联合评审。

## 2. 环境和拓扑

| 环境 | 用途 | 数据与外部接口 |
| --- | --- | --- |
| 开发 | 模块开发与适配模拟 | 合成数据、模拟 CTI/定位/视频，无真实报警线路 |
| 集成测试 | 数据库、消息和终端链路验证 | 隔离测试账号与测试线路，覆盖异常场景 |
| 预生产 | 容量、容灾、升级与恢复演练 | 接近生产拓扑，使用脱敏或合成数据 |
| 生产 | 经批准的真实业务 | 专网与授权接口，受控运维和审计 |

中心内应用至少部署两个实例，分布在独立故障域；数据库采用经验证的主备方案。Kafka 建议至少三个 broker，业务 topic 使用副本数 3、min.insync.replicas=2，生产者 acks=all 并启用幂等；该组合在副本不足时会拒绝写入，应由 Outbox 承接延迟。Kafka 元数据仲裁也需奇数节点并跨故障域布局，最终配置依选定版本验证。

备用中心保留独立网络、配置、数据库副本、消息恢复方案及录音备份。首期不跨高时延链路强行拉伸一个 Kafka 集群；采用独立集群复制或从 Outbox 恢复时，必须验证重复处理和恢复窗口。复制不能替代离线或不可变备份。

## 3. 上线前准备

- 明确忙时呼入、并发通话、坐席数、警力数、事件峰值、录音码率及增长率；根据压测和保留周期计算 CPU、内存、磁盘、IOPS 与带宽，不预设未经验证的机器规格。
- 核准 PSTN/SIP/CTI、定位、PGIS、视频、短信和警务终端接口合同、测试账号、证书和允许调用范围。
- 完成域名、时间同步、证书、密钥托管、访问控制、监控、告警接收渠道和应急联系人配置。
- 网络按入口、业务、数据、管理和外部交换边界划分，按源、目标、协议、端口及方向建立允许清单；数据库、Kafka 和管理端不直接暴露到公网。
- SIP 信令与 RTP 媒体端口范围由通信厂商确认，验证 NAT、专线、录音旁路和双线路切换；不能仅验证 HTTP 入口。
- 对每个状态组件分别确定 RTO、RPO、备份频率、恢复顺序和验收方法，完成恢复演练后冻结指标。

## 4. 构建与制品要求

后续 Java 工程使用 JDK 17、Maven 多 module 为主，父 pom.xml 固定编译 release 为 17 并统一依赖版本。提供 Maven Wrapper 后，CI 执行仓库实际定义的校验与打包任务；Gradle 可另建分支，以相同验收集验证构建等价性。

代码落地时新增 GitHub Actions，执行必要的单元/集成测试、构建及制品发布；只有真实运行成功的工作流可作为构建证据。镜像以提交 SHA 标记并按 digest 部署，保留依赖清单、构建日志、迁移版本与回滚制品。环境密钥不进入仓库或镜像。

可使用以下只读命令查看后续工作流状态；当前仓库没有工作流时不能据此认为验证通过：

```powershell
gh run list --limit 10
gh run view <run-id>
gh run view <run-id> --log-failed
```

## 5. 配置清单

| 配置组 | 需要确定的内容 | 管理要求 |
| --- | --- | --- |
| 应用 | 环境、监听地址、实例标识、并发上限、优雅退出时限 | 按环境独立配置并纳入版本管理 |
| 数据库 | 地址、库名、连接池、超时、迁移版本 | 账号分为运行与迁移角色，凭据放密钥系统 |
| Kafka | bootstrap、认证、TLS、topic、分区、副本、保留期 | 按服务配置 ACL，禁止通配管理权限 |
| Outbox / 重试 | 扫描批量、积压阈值、退避、最大次数、隔离处理 | 所有阈值可观测，重放需要审计 |
| 通信与定位 | CTI 地址、回调认证、媒体范围、接口总超时 | 使用批准的厂商参数与线路配置 |
| 存储 | 录音桶、加密、归档、生命周期、备份 | 保留周期经主管方确认，验证可检索与恢复 |
| 业务 | 辖区、推荐半径、位置有效期、接单时限、自动派警策略 | 初始关闭自动派警，授权后按辖区逐步启用 |
| 安全 | 身份源、MFA、证书、密钥引用、审计出口 | 定期轮换并演练证书到期处理 |

本表是语义清单，尚未定义可直接使用的环境变量名。真实配置键应与实现和启动校验同步生成。

## 6. 部署顺序

1. 备份现有数据和配置，核验可恢复性、变更窗口、应急人工接警方案与旧版制品。
2. 建立网络、DNS、时间同步、证书和最小权限；先验证基础设施及受控测试线路连通。
3. 部署数据库、Kafka、缓存和录音存储，创建账号、topic 与保留策略，验证副本健康和备份任务。
4. 使用专用迁移身份执行可兼容旧版的数据库迁移。先扩展表结构再升级应用，破坏性清理另择窗口。
5. 部署业务应用、Outbox 发布器和消费者，先关闭真实外部副作用，通过健康检查确认依赖及 Schema 兼容。
6. 接入测试坐席、CTI、地图和测试终端，跑通完整受理、派遣、回执、反馈、结案及录音查询链路。
7. 按坐席或辖区逐步引流，核对真实派遣、审计和录音记录，达到批准的观察窗口后扩大流量。

readiness 用于阻止尚未就绪实例接流量；liveness 只检查进程自身可恢复性，避免外部依赖短暂故障引发全体实例重启。健康端点名称由实现定义。滚动退出先停止领取新任务，再等待请求、事务和消费提交结束；CTI 通话排空单独处理。

## 7. 上线验收与证据

| 场景 | 通过条件 | 保存证据 |
| --- | --- | --- |
| 业务闭环 | 测试呼入可受理、派遣、接单、到场、反馈、结案 | 警单与任务标识、状态时间线、脱敏截图 |
| 通信与录音 | 呼叫、人工转接、三方通话与录音可用，失败有明确提示 | 测试呼叫标识、录音校验、厂商日志 |
| 重复与乱序 | 不重复建单、派遣或回退状态，缺口有补偿 | 注入事件、数据库核对、审计记录 |
| MQ 中断 | 警单及 Outbox 可保留，恢复后补发且无重复副作用 | 积压曲线、补发记录和消费结果 |
| 单节点故障 | 剩余实例接流量，任务可恢复 | 故障时间、失败请求、恢复时延 |
| 数据与中心故障 | 无双写所有者，达到批准的 RTO/RPO | 切换记录、丢失/重复数据核对 |
| 权限与审计 | 越权被拒绝、敏感数据脱敏、关键行为可追踪 | 测试矩阵及审计检索结果 |
| 备份恢复 | 在隔离环境恢复数据与录音，业务记录可关联 | 备份标识、校验结果与实测恢复时长 |

性能报告必须记录环境、负载、持续时间、错误率和各阶段 P95/P99。10 秒派警和 60 秒到场不能作为未经业务确认的通用通过标准；真实线路测试须协调安排，不得影响正常接警。当前仓库尚无上述验收证据。

## 8. 回滚与容灾操作

应用故障时停止扩大流量，必要时关闭自动派警，保留人工处置；回退到已验证的镜像 digest，核对数据库与事件兼容性。已发出的派遣和通知不能随应用回滚撤销，必须按任务现状对账。

数据库不自动执行破坏性反向迁移。恢复旧备份前先确认增量数据的保留与补偿方案；数据库恢复可能重新出现已处理 Outbox，需要同时检查消费去重记录和外部 commandId 状态。

中心故障按“确认故障 → 隔离旧主及旧派遣执行器 → 确认复制水位与可能损失 → 提升备用数据服务 → 接管应用与通信路由 → 核对警单、任务、消息及录音 → 恢复引流”执行。无法隔离旧主时不得贸然双中心同时写入。回切使用相同的唯一所有者原则，不能直接恢复旧中心流量。

## 9. 日常运维与交付缺口

监测呼入失败、派遣超时、位置过期、Outbox 最老积压、消费延迟、复制滞后、存储容量、录音缺失和证书到期。告警阈值按预生产基线确定，告警内容不含敏感警情正文。定期完成备份校验、恢复演练、权限复核、密钥轮换和失败任务对账。

可执行部署交付仍需补齐：业务代码及测试、Maven/Gradle 构建、GitHub Actions、镜像及 digest、数据库迁移、部署清单、厂商配置模板、监控规则、容量报告和真实恢复报告。完成这些内容前，项目状态为“设计文档基线”。
